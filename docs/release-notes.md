### v0.2.8 · 安装与更新改进

- 首次安装和更新统一安装到系统“应用程序”。新版启动确认成功后，清理本次更新中已验证的旧应用；失败时保留必要恢复材料。
- 安装器保留“安装 / 更新、重新尝试启动、恢复旧版、导出诊断信息”四个按钮，移除位置选择、安装路径展示和历史清理入口。
- “重启并更新”仅显示“确认 / 取消”。确认后忽略未保存输入，不自动保存音乐、片段或标签草稿；已经提交的操作等待完成后再退出。
- 增加已签名兼容信息、已验证下载复用、持久化安装事务、并发保护及受管缓存清理。提交后的清理失败可以重试，不撤销已成功的安装。
- 发布流程先上传并核对完整资产，再公开 Release，减少不完整更新包被分发的机会。

### 原来的音乐库继续使用

数据库 schema 保持为 3。保留 `settings.json`、原 `library.db` 路径及原始音频，音乐、片段、标签、专辑标签和候选清单无需重新导入。安装器不会搬迁音乐库，也不会随应用恢复而回滚数据库。

- 移动硬盘未连接或音乐库不可用时等待重试，不创建替代空库。
- 删除音乐或片段仍只删除记录，不删除原始音频。
- 更新后正常启动仍会按已有逻辑记录应用版本、同步音频位置和书签。

### 从旧版升级

- v0.2.6 / v0.2.7 用户可使用应用内“检查更新”。
- 旧客户端在自定义目录拒绝检查更新时，请打开新版 DMG。安装器只识别当前交接来源、正在运行的正式旧应用、用户“应用程序”内的副本及已记录的迁移来源，不扫描全盘。按提示保存并退出不支持退出交接的旧版后继续安装。
- 已关闭且位于未知位置的旧副本不会自动发现或删除；旧位置有未完成恢复事务时，先处理恢复。
- 缺少音乐库位置配置时，选择“打开已有音乐库”，指向原 `library.db` 所在文件夹。旧默认库位于 `~/Library/Application Support/com.musicmanager.app/library.db`。

### 下载与安装

| 设备 | 下载文件 |
| --- | --- |
| Apple Silicon Mac | `music-manager_{{version}}_aarch64.dmg` |
| Intel Mac | `music-manager_{{version}}_x64.dmg` |

1. 打开对应 DMG，双击“安装与更新声场档案”。
2. 点击“安装 / 更新”，按需完成管理员授权，等待新版启动确认。目标固定为 `/Applications/声场档案.app`。
3. macOS 首次阻止打开时，可在“系统设置 → 隐私与安全性”允许打开。
4. 未完成的更新可在安装窗口重试启动、受控恢复旧版或导出诊断。成功提交并清理旧版后，不再提供本地旧版恢复；后续使用同版修复安装或更高版本。

安装器和应用使用免费 ad-hoc 签名，更新包使用独立数字签名；未进行 Apple Developer ID 签名或公证，首次系统放行限制仍然存在。

`install-macos.sh` 保留为旧命令兼容入口，打开同一个图形安装器，不直接删除或覆盖应用。
