# 安装更新变更清单

核对基线：`origin/main` / `cb2a063`；范围为本分支所有未提交改动（包括新增文件）。2026-11-04 更新。最终以用户要求为准：统一装到系统“应用程序”，成功后清理可验证的旧位置副本。早期“原位置更新”和“可选用户安装”的计划已被替代。

## 用户能看到的变化

| 项目 | 原有行为 | 当前实现 |
|---|---|---|
| 首次安装 | 系统位置无副本时选择用户应用目录 | 固定系统 `/Applications/声场档案.app`，不让用户选择 |
| 已有旧位置安装 | 在原位置更新 | 将新版装到系统应用程序；旧副本在启动确认后删除 |
| 安装器主窗口 | 原有四个按钮 | 保留安装/更新、重试启动、恢复旧版、导出诊断；不显示安装路径 |
| 额外安装器入口 | 本轮中途新增过 | 历史清理、查看位置、重新选择位置以及工具菜单已移除 |
| 安装成功 | 保留旧应用备份 | 提交后自动清理；清理失败保留待处理状态，不撤销成功安装 |
| 更新前未保存编辑 | 提醒自行保存 | 只显示「确认 / 取消」；确认后忽略未保存输入，不自动保存草稿；已提交的写入仍等待完成 |
| 更新下载 | 主要依赖进程内状态 | 已下载并校验的包可重开后复用；重新检查不必重复下载 |
| 取消 | 无独立取消入口 | 应用内更新在下载、校验、准备阶段显示取消；替换阶段不能取消 |
| 更新异常 | 普通错误信息 | 增加兼容性、空间、冲突、退出、启动、事务与清理错误分类 |
| 应用内更新面板 | 版本、说明与进度 | 仍有安装状态/架构、Finder 定位，以及仅待清理时出现的“重试清理”；这些属于主应用面板，不是安装器四按钮窗口 |
| 手动安装时旧 App 运行 | 旧退出机制 | 支持新退出协议的客户端使用同一确认/取消提示，确认后忽略草稿并等待已提交写入；不支持的旧版要求用户自行退出 |

## 安装与数据保护实现

| 改动 | 用途/范围 |
|---|---|
| 安装状态与日志分离、原子写入、前一份记录 | 进程退出后仍能恢复和对账；损坏记录不能直接忽略 |
| 目标锁、启动锁、短期提权执行器 | 防止并发替换；系统目录操作限定命令和路径，不使用常驻服务 |
| 先暂存、校验、再替换 | 旧应用退出前完成准备；再次验证目标未被换掉 |
| 下载和目标卷空间预检、外部命令超时 | 减少退出后才发现失败；目标卷余量为展开大小的 20% 与 100 MiB 中较大者 |
| 后端写入门禁 | 更新退出时拒绝新写入，等待接受的写入完成；覆盖音乐、片段、标签、候选、导出与库切换等写入命令 |
| 启动确认增加实际路径、稳定存活检查 | 核对令牌、PID、版本、路径；ready/待选库/缺盘处理有效持续两秒后提交 |
| 迁移来源持久化 | 保存旧路径、版本、可执行文件摘要、目录 inode/device；成功后复核再删除，失败时保留 |
| 迁移发现范围 | 更新来源参数、同 identifier 正在运行的 App、用户 Applications 副本；不全盘扫描 |
| 迁移清理权限 | 旧来源仅以当前用户权限删除；不把任意旧路径交给 root 执行器 |
| 自动清理与保留规则 | 已提交旧版、暂存、下载、内部安装器；运行中安装器延迟处理；日志按归属和期限维护 |
| 旧协议适配 | 保留 0.2.6/0.2.7 交接、安装器名称及内嵌应用位置，新增协议2路径 |
| 历史清理内部方法 | 仍保留受限的历史记录/清理实现与测试；已无普通用户入口，也没有自动清扫未知旧 App |

原有的签名检查、版本/架构校验、启动报告、恢复旧版、数据库兼容预检和诊断导出本来就存在。这轮扩展其状态、清理和失败边界，不能全部算作新增功能。

## 发布、开发与测试变化

| 改动 | 说明 |
|---|---|
| 独立签名兼容元数据 | 绑定版本、架构、最低系统/客户端、协议、schema、大小、DMG 摘要和公钥指纹 |
| 构建产物校验 | 检查实际 App 身份、架构、内置公钥、端点及后续更新能力 |
| 草稿发布 | 先上传完整资产并核对远端大小/摘要，再公开；只重试同提交的可信草稿 |
| CI 构建时机 | PR 只测试与校验发布配置；main 新版本测试成功后双架构各构建一次并发布；手动仍可只构建。CLI 独立缓存由构建/发布任务复用 |
| 旧仓库地址兼容 | 旧客户端固定 AI-AQI 地址；发布前验证它仍重定向至当前仓库 |
| 密钥过渡 | 增加旧钥授权新钥的过渡验证；未实际轮换正式密钥 |
| Rust 依赖 | 新增直接依赖 sha2、futures-util、libc，用于摘要、取消和锁 |
| IPC | 新增安装/更新状态、取消、退出准备/撤销、清理重试、Finder 定位与手动安装退出响应；原三个更新命令保留 |
| 隔离验收 | 独立 identifier、归属清单、历史标签客户端构建、成功清理测试产物；不递归删除整个 target |
| 测试 | 新增更新确认/忽略草稿、缓存/签名元数据、迁移/清理/故障、草稿发布和原生窗口检查；同步预览 mock、README 与设计说明 |

## 没有改动与仍存在的边界

- 本次发布目标为 0.2.8，音乐库 schema 仍是 3；没有搬迁音乐库或修改原始音频。
- 2026-11-04 用户已授权提交、创建 PR 和准备 v0.2.8；合并 main 后由 CI 自动发布。没有修改正式密钥，没有清理开发者此前的历史 App。
- 没有加入 Sparkle、Developer ID、公证、后台常驻服务或前端 npm 依赖。
- 旧客户端若在自定义位置拒绝检查更新，需要使用新 DMG。新安装器可以识别正在运行的旧副本；已关闭且位于未知自定义位置的副本不会凭空被发现或全盘搜索。
- 来源身份不符、被替换、符号链接、开发目录、DMG、权限不足或旧位置有未完成恢复事务时，保留相关材料并停止对应操作或记录待清理，不强删。
- 当前持久化的是完成校验的下载与安装事务；没有断点续传，也没有把每一瞬间的下载进度持久化。`get_update_status` 目前主要返回 idle/ready，而非完整安装阶段流。
- 当前同版安装可走完整事务，但没有专门改成“修复安装”的按钮文案。等待写入超时当前取消更新并提示重试，尚无任务类别列表。
- Intel 实机、真实系统管理员/跨账户授权、不同 macOS、物理断电未实测；模拟结果不替代实测。正式 GitHub 草稿发布与密钥轮换也没有实际执行。

这些边界属于当前实现状态，不能用“整体计划全部完成”概括。
